A file explorer for just recipes — and the jobs they become

just-tui reads just --dump and lays a justfile out the way a file manager lays out a disk: modules are directories, recipes are files, and the right-hand split shows each recipe's documentation above its real source. Then it submits them to Slurm and watches what happens.

Read a justfile properly

The full comment block above a recipe, its parameters and defaults, its dependencies split into before and after, its attributes — not the one line just --list gives you.

Submit to Slurm

A form that submits the recipe, not a generated script. Partitions, accounts and QoS are read off the cluster; limits are checked before you commit.

Watch the queue

Running and finished jobs in one list, with live memory and CPU against what they reserved, and the tail of the log that says why one failed.

Installing

just-tui is not on crates.io yet, so install it from a clone:

git clone https://github.com/4less/just-tui
cd just-tui
cargo install --path .

It needs just on PATH — it reads just --dump --dump-format json and the justfiles that dump points at. Slurm's client tools (squeue, sbatch, sacct, sstat, scontrol) are needed only for the cluster features; without them the rest works and the Slurm form falls back to free text.

Check what you have installed — the build stamps itself with the commit it came from, which is what tells two installs of one release apart:

$ just-tui --version
just-tui 0.2.0 (v0.2.0-4-g8a9c685, 2026-09-11)

Quickstart

just-tui                 # browse the justfile found from here
just-tui ../other        # browse another project
just-tui -f build.just   # a particular file
just-tui --list          # plain listing, no TUI
just-tui --no-global     # project recipes only

Then: ↑↓ to move, → to open a module, Enter to run a recipe, s to submit it to Slurm, S to watch the queue, ? for every key.

Running a recipe leaves the TUI, streams the output to the normal terminal, and comes back on any key — so interactive recipes keep working.
